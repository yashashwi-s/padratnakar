# Reader audit — 28 September 2026

Scope: source inspection of reader layout, sharing, startup, navigation, offline configuration and release documentation. All 81 JavaScript tests passed. This audit did not include a physical Android/iOS device, live deployment or Play Console review. Findings below distinguish observed implementation issues from recommended testing. No application behavior changed during this audit.

## Priority fixes

1. **Unnecessary image rendering on the website.** `src/components/PadTypography.jsx:77` schedules PNG preparation for every current pad, including web/PWA. `src/lib/share-pad.js:133` only shares text on web. Gate preparation to native platforms; this avoids font embedding, SVG decoding and canvas work after web navigation.
2. **Share cache may retain pre-font collection geometry.** The preparation effect runs before collectionMetrics exists and again when it arrives. `preparePadShare` caches solely by pad key and returns the original promise without replacing it. On a sufficiently slow font load the native shared picture can use fallback stretched geometry even after the reader corrects itself. Require ready metrics before preparation and either include layout revision in the key or invalidate the provisional entry. Add a delayed-font regression test.
3. **Long titles still stretch glyphs.** `PadTypography.jsx:162` forces every centered heading over 29 JavaScript characters to a fixed width with spacingAndGlyphs, even when its natural width fits. Devanagari character count is not visual width. Measure headings and only shrink when necessary; never expand to the full line width. Kallolini also retains glyph compression when natural width exceeds a source line box. Audit these exceptions visually.
4. **Startup has no upper wait bound.** `src/main.jsx:29` waits for font loading before removing the overlay. A stalled first web font request can hold the launch screen indefinitely; rejection handling does not address a pending request. Use a bounded launch wait, allow fallback reading and recalculate when the font arrives.

## Next improvements

- Add a PWA update notice and explicit offline-ready status. Current service-worker config deliberately waits for old clients to close, but the UI does not tell a standalone-app user an update is waiting. Test an actual old-to-new installed PWA update and cold offline launch.
- Split collection data out of the initial JavaScript bundle. The current main bundle is roughly 6.5 MB on disk. Lazy loading can reduce parsing/startup work, but retain precaching of all collections for offline access.
- Add bookmark export/import. Current device-local storage offers no user-controlled backup or migration path.
- Extend UI regression checks to actual computed fonts, measured heading widths, section/subsection navigation and delayed font loading. The passing structural tests do not detect all visual distortions.
- Refresh frontend handoff and release documentation: desktop sharing is text plus link now, the app has four main collections, and some historical layout/test-count descriptions are stale. Privacy policy already distinguishes web analytics from the native app; do not incorrectly treat that as an undisclosed native analytics integration. Publisher/contact placeholders still need finalization and hosting.
- Validate native splash masking, large system text, rapid swipes, pinch-plus-scroll, shared-image output and back behavior on physical Android, plus installed PWA on iOS. Source inspection is not sufficient evidence of smooth device behavior.

Recommended order: sharing readiness/performance, heading measurement, bounded startup, then installed-PWA/device testing and release documentation.

## Follow-up implemented

All four priority fixes above are implemented. Web/PWA navigation no longer schedules PNG rendering. Native pre-generation waits for measured layout and caches by SVG revision; explicit sharing waits for font measurement frames and rejects an unready reader. Font requests reuse one promise, with retry after failure. Centered headings use actual rendered width and never expand merely because they contain many characters. The launch overlay has no minimum hold and caps its font wait at 200 ms after application execution, with a 120 ms fade. This is not a measurement of total cold startup: download and JavaScript parsing still precede that handoff.

Validation: full check passed, including the font request/retry regression and all 21,672 canonical line positions. The long Jayanti 17 heading was visually checked in the browser. Physical-device latency and native sharing remain device-test items. Kallolini source-box body compression is unchanged; the heading fix does not alter canonical text or body layout.
